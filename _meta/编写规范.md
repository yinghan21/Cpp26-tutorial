# 编写规范（内部，第 1 版）

> 本文件是这套教程的“宪法”。所有章节必须遵守，改稿前先读一遍。

## 一、读者定位

- 读者：会一点点编程或完全不会，但**目标是把 C++26 用到能干活**。
- 语气：直接、具体、有结论。给命令、给输出、给踩坑点，不写“由于历史原因我们要注意……”这种空话。
- 每一节都要回答三个问题：**是什么 / 为什么这样写 / 我实际会怎么用**。

## 二、硬性代码约定

1. 每个示例的第一行必须是 `import std;`，**并且这一行后面必须换行**。
   - MSVC 实测：写成 `import std; int main(){...}` 会报 `error C7586: "" 指令必须在同一行上以 ";" 结尾`。这是个真实坑，教程要单独提。
2. 禁止 `#include <...>`、禁止 `using namespace std;`、禁止 `printf`（除非专门讲互操作/`std.compat`）。
3. 输出统一 `std::println` / `std::print`。格式串里的中文**可以**，实测正常。
4. 类型写全或用 `auto`，不要 C 风格强制转换；用 `static_cast`。
5. 代码注释用中文、短句、只解释“为什么”，不解释“这行在赋值”。
6. 缩进 4 空格；`{` 不换行（K&R）；每行 ≤ 100 字符。
7. 示例要**完整可编译**：包含 `int main()`，不能是残缺片段（除非明确标为 `// 片段`）。

## 三、已验证的支持矩阵（2026-11，本机实测）

MSVC 19.51（VS 18 / `vcvars64`，`/std:c++latest`，`import std;`）：

| 能用 | 说明 |
| --- | --- |
| `std::println` / `std::print` / `std::format` / `format_to` | 含 `{:>8.3f}`、`{:x}`、`{:b}`、`{:*^9}`、`{:+#x}`、`{:.3e}` |
| `std::expected` + `and_then` / `transform` / `value_or` | |
| `std::generator<T>` + `co_yield` | 协程完整可用 |
| `std::jthread` / `stop_token` / `mutex` / `condition_variable` / `atomic` / `atomic_ref` | |
| `std::latch` / `barrier` / `counting_semaphore` / `async` / `future` | |
| `std::flat_map` / `flat_set` | C++23 |
| `std::mdspan` | |
| `std::stacktrace` | |
| `std::move_only_function` / `std::function` | |
| `views::enumerate` / `chunk` / `zip` / `adjacent<N>` / `join_with` / `cartesian_product` / `repeat` / `split` | C++23 ranges 齐全 |
| `std::ranges::to<std::vector>()` / `fold_left` | |
| 直接 `std::println("{}", vector)` | 打印成 `[1, 2, 3]`（range formatter 可用） |
| `std::string::contains` / `std::to_underlying` / `std::byteswap` / `std::bit_cast` | |
| `std::filesystem` / `std::chrono`（含 `current_zone()` 时区库）/ `std::random` / `std::regex` / `std::numbers` | |
| `constexpr std::vector` | |
| `std::source_location` | |
| `std::osyncstream` | |
| `std::includes` 之外的 `<numeric>`、`<bit>` 全量 | |
| 自写模块 `export module` / `import 自定义模块` | 见 `build-project.ps1` |
| `import std.compat;` | 需要先生成 `std.compat.ifc`；`build.ps1` 自动处理 |

**不能用（写出来会编译失败，教程只能在“支持矩阵”里讲，不能当作可运行示例）**：

| 特性 | 实测报错 |
| --- | --- |
| 契约 `[[pre: ...]]` | C2760 |
| 反射 `^^T` | C2062 |
| 包索引 `t...[0]` | C2760 |
| `= delete("原因")` | C2059 |
| 占位符 `auto _ = ...` 重复定义 | C2374 |
| `std::inplace_vector` / `std::hive` / `std::simd` / `std::execution` / `std::rcu_*` / `std::scope_exit` | C2039 不是 std 成员 |

**其它实测坑**：

- `std::println("{}", 指针)` 编译失败（`C2338: Cannot format an argument`）。要打印地址用 `std::bit_cast<std::uintptr_t>(p)` 或 `std::format("{:x}", 地址)`。
- `std::spanstream` 存在但**没有** `str()` 成员；能 `<<` 能 `.rdbuf()->view()`，讲的时候别写 `str()`。
- 头文件单元 `import "x.h";` 需要先 `cl /exportHeader x.h`，再 `cl /headerUnit "x.h=x.h.ifc"`。只在讲互操作那一节提，别当日常写法。
- 用 `/utf-8` 编译用户代码、`/D_UTF8` 编译 `std.ixx`，否则会冒 `C5050` 警告。`build.ps1` 已经这么干了。

clang 22（`zig c++ -std=c++26`，通过 `build-clang.ps1`）：`#embed`、包索引、`= delete("原因")`、`_` 占位符可用；契约/反射仍不行。只有 [[46 C++26 新特性全览]] 用 clang。

## 四、Markdown 结构模板（顺序固定）

```markdown
---
title: <标题>
tags: [cpp, cpp26, <分类>]
chapter: <单元号 1-7>
order: <两位数>
created: 2026-11-05
---

# <标题>

> [!info] 本节目标
> - 3～6 条，动词开头

> [!tip] 先看结论（可选，但推荐）
> 用 2～3 句话说清关键点

## 一、<小节>
## 二、<小节>
（小节数 4～9 个，用 一、二、三…… 编号）

## 完整示例（已实测）
（贴 samples 里那段的完整源码 + 构建命令 + 真实输出）

## 常见错误与排查
（表格：现象 / 报错 / 原因 / 改法）

## 练习
1. …（4～6 题，由易到难）

> [!success]- 参考答案
> 1. …（必须给全，不能“略”）

---

上一节：[[..]] ｜ 下一节：[[..]]
```

要求：

- 每节至少 **1 个全景表**（选型/对比/复杂度/常见错误，四选一以上）。
- 至少 **6 个代码块**，且都要能编译（片段要标 `// 片段`）。
- 输出块一律用 ` ```text `，内容必须是**真跑出来的**，不许编。
- 用 `> [!warning]` 标坑，用 `> [!tip]` 标技巧，用 `> [!info]` 标概念澄清。
- 结尾必须有“上一节 / 下一节”，用 Obsidian 双链：`[[16 类与对象：构造、析构与 RAII]]`。

## 五、深度要求（硬指标）

- 每个 `.md` **≥ 260 行**，其中正文（不含示例）中文 ≥ 5000 字。
- 每节至少讲清 **1 个底层机制**（内存布局、调用约定、模板实例化、复杂度、异常安全等级…），不能只罗列 API。
- 每个 API 都要给出：签名要点、典型用法、边界情况（空/越界/失败）、常见误用。
- 练习答案要能直接跑。

## 六、示例代码与验证流程（强制）

1. 文件名：`samples\<order>_<短名>.cpp`，例如 `samples\13_sum_types.cpp`；多文件工程放 `samples\proj_<名字>\`。
2. 写完后**必须**实际运行：

```powershell
.\build.ps1 samples\13_sum_types.cpp
.\build-project.ps1 samples\proj_json        # 模块/多文件工程
```

3. 把真实输出粘贴进 `## 完整示例（已实测）`。
4. 编译不过就改代码，不许改教程里的“预期输出”；确认是编译器不支持的特性，就换成能跑的写法并把限制写进“支持矩阵”。
5. 有警告的要处理掉（`/W3` 下不能有 warning）。

## 七、交叉引用与术语

- 章节双链必须和真实文件名完全一致（含中文标点）。
- 术语统一：**接口单元**（module interface unit）、**实现单元**、**翻译单元**、**所有权**、**生命周期**、**值类别**、**RAII**、**零法则**、**视图**（view）、**借用**（borrow）。
- 单位统一：`std::size_t`、`std::int64_t`、`std::uintptr_t` 写全 `std::`。

## 八、绝对不要做

- 不要写“本章略”“详见后文”这类空占位。
- 不要复制 cppreference 的英文原文当正文。
- 不要在教程里出现 `#include`、`printf`、`malloc`、`char*` 风格的“现代写法”示范（对比时可以出现，但要标注“不要这样写”）。
- 不要用未验证的输出。
